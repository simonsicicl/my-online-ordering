### Key Handler Responsibilities

#### `src/handlers/pre-signup.ts`
- Cognito trigger — fires before user is created
- Auto-confirm email for dev environment (`AppEnv === 'dev'`)
- Block disposable email domains (future hook)
- Export: `handler` typed as `PreSignUpTriggerHandler`

#### `src/handlers/post-confirmation.ts`
- Cognito trigger — fires after email is confirmed
- Creates a row in the `users` table (`id = event.userName` which is Cognito sub)
- Creates a `user_profiles` row for the new user
- Uses `db.transaction()` for both inserts
- Export: `handler` typed as `PostConfirmationTriggerHandler`

#### `src/handlers/token-validator.ts`
- API Gateway Lambda Authorizer
- Fetches Cognito JWKS and verifies RS256 JWT
- Extracts `sub`, `email`, `custom:globalRole` from claims
- Returns `APIGatewaySimpleAuthorizerResult` with `isAuthorized` and context `{ userId, email, role }`
- **Caches JWKS** in module scope (not Redis — JWKS rarely changes)
- Export: `handler` typed as `APIGatewayRequestAuthorizerHandlerV2`

#### `src/handlers/register.ts`
- `POST /api/v1/auth/register` (public)
- Calls `CognitoIdentityProviderClient` → `SignUpCommand`
- Returns `RegisterResponse`

#### `src/handlers/login.ts`
- `POST /api/v1/auth/login` (public)
- Calls Cognito `InitiateAuthCommand` with `USER_PASSWORD_AUTH` flow
- Returns `LoginResponse` (tokens + user object)
- Queries `users` table to get `globalRole` for response

#### `src/handlers/refresh.ts`
- `POST /api/v1/auth/refresh` (public)
- Calls Cognito `InitiateAuthCommand` with `REFRESH_TOKEN_AUTH` flow
- Returns new `accessToken` + `expiresIn`

#### `src/handlers/logout.ts`
- `POST /api/v1/auth/logout` (requires JWT)
- Calls Cognito `GlobalSignOutCommand`
- Returns `{ message: "Logged out successfully" }`

### `src/db/schema.ts`

Auth service owns the `users` and `user_profiles` tables only. Copy exact definitions from `db.spec.md`.

### `template.yaml` Key Points

```yaml
# services/auth-service/template.yaml
Parameters:
  AppEnv:         { Type: String }
  CognitoUserPoolId:     { Type: AWS::SSM::Parameter::Value<String>, Default: /myordering/dev/cognito/user-pool-id }
  CognitoClientId:       { Type: AWS::SSM::Parameter::Value<String>, Default: /myordering/dev/cognito/client-id }
  CognitoRegion:         { Type: AWS::SSM::Parameter::Value<String>, Default: /myordering/dev/cognito/region }
  DatabaseHost:          { Type: AWS::SSM::Parameter::Value<String>, Default: /myordering/dev/db/host }
  # ... other DB params

Resources:
  AuthApi:
    Type: AWS::Serverless::HttpApi
    Properties:
      StageName: !Ref AppEnv
      # No authorizer here — auth endpoints are public

  TokenValidatorFunction:
    Type: AWS::Serverless::Function
    Properties:
      FunctionName: !Sub "auth-token-validator-${AppEnv}"
      Handler: src/handlers/token-validator.handler
      # No ReservedConcurrentExecutions — this is NOT a DB function
      # No VPC — must reach Cognito JWKS endpoint

  # Cognito triggers must be in the same template OR attached via UpdateUserPool
  PreSignupFunction:
    Type: AWS::Serverless::Function
    Properties:
      FunctionName: !Sub "auth-pre-signup-trigger-${AppEnv}"
      Handler: src/handlers/pre-signup.handler

Outputs:
  TokenValidatorArn:
    Description: "Lambda Authorizer ARN — pass to all other service templates"
    Value: !GetAtt TokenValidatorFunction.Arn
    Export:
      Name: !Sub "myordering-TokenValidatorArn-${AppEnv}"
```

> **Critical**: `TokenValidatorFunction` must NOT be placed in the VPC — it needs outbound internet access to fetch Cognito JWKS. DB-connected functions go in VPC; authorizer does not.

### Key Handler Responsibilities

#### `src/handlers/get.ts`
- Public — no JWT required (`APIGatewayProxyHandlerV2`)
- Cache key: `store:{storeId}`, TTL 10 min
- Returns 404 with `NOT_FOUND` if store does not exist
- Response: `Store` object

#### `src/handlers/create.ts`
- Auth: `MERCHANT` or `ADMIN` only
- Reads caller identity from `event.requestContext.authorizer.lambda`
- Validates `CreateStoreRequest` via Zod schema
- Inserts into `stores` table
- Publishes `Store.Created` EventBridge event
- Returns 201 `{ id, name, createdAt }`

#### `src/handlers/update.ts`
- Auth: `MANAGER`, `MERCHANT`, `ADMIN`
- Partial update — only patches provided fields
- Invalidates `store:{storeId}` Redis cache after update
- Publishes `Store.Updated` EventBridge event
- Returns 200 updated `Store` object

#### `src/handlers/update-status.ts`
- Auth: `MANAGER`, `MERCHANT`, `ADMIN`
- Validates caller has access to this `storeId` (check `store_staff` table for MANAGER role)
- Updates `acceptingOrders` field
- Invalidates Redis cache
- Publishes `Store.StatusChanged` EventBridge event
- Returns `{ id, acceptingOrders, updatedAt }`

import { drizzle } from 'drizzle-orm/postgres-js';
import postgres from 'postgres';
import { config } from './config';

// Module-level singleton — reused across warm Lambda invocations
let client: ReturnType<typeof postgres> | undefined;

export function getDb() {
  if (!client) {
    client = postgres({
      host:     config.dbHost,
      port:     config.dbPort,
      database: config.dbName,
      username: config.dbUser,
      password: config.dbPassword,
      ssl:      config.dbSsl ? 'require' : false,
      max:      config.dbMaxConnections,
    });
  }
  return drizzle(client);
}

export const db = getDb();

let redisClient: ReturnType<typeof createClient> | undefined;

export async function getRedis() {
  if (!redisClient) {

### `src/lib/errors.ts`

```typescript
type ErrorCode =
  | 'VALIDATION_ERROR' | 'UNAUTHORIZED' | 'FORBIDDEN' | 'NOT_FOUND'
  | 'CONFLICT' | 'OUT_OF_STOCK' | 'PAYMENT_FAILED' | 'RATE_LIMIT_EXCEEDED'
  | 'INTERNAL_ERROR';

export class AppError extends Error {
  constructor(
    public readonly code: ErrorCode,
    message: string,
    public readonly statusCode: number,
    public readonly details?: unknown[],
  ) {
    super(message);
    this.name = 'AppError';
  }
}
```

### `src/lib/validation.ts`

```typescript
import { z, ZodSchema } from 'zod';
import { AppError } from './errors';

export function validateBody<T>(body: string | null | undefined, schema: ZodSchema<T>): T {
  if (!body) throw new AppError('VALIDATION_ERROR', 'Request body is required', 400);
  let parsed: unknown;
  try {
    parsed = JSON.parse(body);
  } catch {
    throw new AppError('VALIDATION_ERROR', 'Invalid JSON', 400);
  }
  const result = schema.safeParse(parsed);
  if (!result.success) {
    throw new AppError('VALIDATION_ERROR', 'Validation failed', 400,
      result.error.errors.map(e => ({ field: e.path.join('.'), message: e.message }))
    );
  }
  return result.data;
}
```

## Notes

### Why `auth-service` does not use Lambda Authorizer on its own API

Auth endpoints (`/register`, `/login`, `/refresh`) are **public** — they accept unauthenticated requests. Only `/logout` requires a JWT, and this is verified by calling Cognito directly inside the handler.

### Cognito triggers vs. SAM stack

SAM cannot attach Lambda triggers to an **existing** Cognito User Pool (the User Pool was created in the foundation stack). You must call `aws cognito-idp update-user-pool` or `aws lambda add-permission` manually after deploying `auth-service`. This is handled in Step 6 above.

### `token-validator` must NOT be in the VPC

It calls the Cognito JWKS endpoint (`https://cognito-idp.{region}.amazonaws.com/{userPoolId}/.well-known/jwks.json`), which requires internet access. Lambda functions in a VPC without a NAT Gateway cannot reach the internet.

### Phase 3 prerequisite

Phase 3 (Menu & Order Services) requires:
- `auth-token-validator-dev` ARN (available after Phase 2 Step 6)
- `users` and `stores` tables populated (at least one store must exist for menu testing)
